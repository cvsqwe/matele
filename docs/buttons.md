# Кнопки

Кнопки в matele это кнопки под сообщением бота. Человек нажимает кнопку, бот получает событие и что-то делает: меняет сообщение, присылает новое, показывает уведомление.

Клавиатура состоит из рядов, ряд из кнопок:

```python
from matele import Button, Keyboard

keyboard = Keyboard([
    [Button("Да", "answer:yes"), Button("Нет", "answer:no")],
    [Button("Сайт", url="https://example.com")],
])
await ctx.reply("Продолжим?", keyboard)
```

Здесь два ряда: в первом две кнопки рядом, во втором одна на всю ширину.

Кнопка бывает трёх видов:

- `Button(text, data)`: при нажатии бот получает строку `data`;
- `Button(text, url=...)`: открывает ссылку, бот о нажатии не узнаёт;
- `Button(text, app=...)`: открывает мини-приложение бота, см. [Мини-приложения](mini-apps.md).

Клавиатуру принимают все методы, которые отправляют или меняют сообщение: `ctx.reply`, `ctx.reply_file`, `ctx.edit`, `ctx.show`, `bot.send_message`.

## Данные кнопок

Данные кнопки это строка, которая вернётся боту при нажатии. В простом случае можно придумать формат самому и разбирать его руками, но это быстро надоедает: строки нужно собирать в одном месте, разбирать в другом и следить, чтобы форматы не разошлись.

В matele данные описываются классом. Декоратор `@callback` превращает класс в неизменяемый dataclass и запоминает его префикс:

```python
from typing import Literal

from matele import Button, CallbackData, Context, Keyboard, callback


@callback("order:set")
class SetStatus(CallbackData):
    order_id: int
    status: Literal["paid", "shipped"]


keyboard = Keyboard([[
    Button("Оплачен", SetStatus(42, "paid").pack()),       # "order:set:42:paid"
    Button("Отправлен", SetStatus(42, "shipped").pack()),
]])


@dp.callback(SetStatus)
async def set_status(ctx: Context, payload: SetStatus):
    await orders.set_status(payload.order_id, payload.status)
    await ctx.edit(f"Заказ {payload.order_id}: {payload.status}")
```

`pack()` собирает строку: префикс и значения полей через двоеточие. При нажатии matele находит класс по префиксу, разбирает строку обратно и вызывает хендлер, зарегистрированный для этого класса. В хендлер вторым аргументом приходит готовый объект, где `order_id` уже `int`, а `status` гарантированно одно из двух значений.

### Типы полей

Поля могут быть таких типов:

| Тип | Как выглядит в строке |
|---|---|
| `int` | `42` |
| `str` | как есть |
| `bool` | `1` или `0` |
| `datetime.date` | `2026-11-10` |
| `Literal["a", "b"]` | одно из перечисленных значений |

Двоеточие разделяет поля, поэтому значение `str` с двоеточием внутри допускается только в последнем поле. Если нарушить это правило, `pack()` бросит `ValueError`.

Если значение в строке не подходит под тип поля, например в `int` пришли буквы, кнопка считается устаревшей (см. ниже), а не роняет бота.

### Префиксы

Префикс должен быть уникальным. Если два класса объявят один и тот же префикс, при импорте будет ошибка, так что две части бота никогда не перехватят кнопки друг друга.

Префиксы удобно строить по схеме «раздел:действие»: `order:set`, `order:cancel`, `menu:home`. Один префикс может быть началом другого. Тогда при разборе выигрывает самый длинный подходящий.

### Кнопки без полей

Для кнопок, у которых нет данных, есть `action`. Он сразу возвращает готовый объект:

```python
from matele import action

HOME = action("menu:home")

keyboard = Keyboard([[Button("На главную", HOME.pack())]])


@dp.callback(HOME)
async def home(ctx: Context, payload):
    await ctx.show("Главное меню", main_keyboard)
```

В `@dp.callback()` можно передать и класс, и такой объект.

### Новые поля и старые кнопки

Кнопки, отправленные вчера, остаются в чатах и после обновления бота. Человек может нажать кнопку, которую бот прислал месяц назад, и данные в ней будут в старом формате.

Чтобы добавить поле, не сломав старые кнопки, дайте ему значение по умолчанию и добавьте в конец класса:

```python
@callback("order:set")
class SetStatus(CallbackData):
    order_id: int
    status: Literal["paid", "shipped"]
    notify: bool = True
```

Поля в конце, равные значению по умолчанию, в строку не попадают. Старая строка `"order:set:42:paid"` разберётся с `notify=True`, а новые кнопки с `notify=True` будут выглядеть точно так же.

### Устаревшие кнопки

Бывает, что кнопку разобрать уже нельзя: класс удалили, поменяли тип поля или убрали поле из середины. Бот от этого не упадёт. Такое нажатие не попадёт ни в один `@dp.callback()`, но попадёт в `@dp.raw_callback()`, а `ctx.payload` будет `None`:

```python
@dp.raw_callback()
async def outdated(ctx: Context):
    await ctx.answer("Эта кнопка устарела, нажмите /start", alert=True)
```

Сырая строка данных в этом хендлере лежит в `ctx.callback.data`.

Если такого хендлера нет, matele просто ответит на нажатие, чтобы кнопка перестала показывать ожидание. Человек при этом ничего не увидит, поэтому хендлер для устаревших кнопок лучше завести.

`@dp.raw_callback()` получает вообще любые нажатия, для которых не нашлось хендлера по классу, в том числе разобранные. Хендлеры по классу проверяются в порядке регистрации вместе с ним, так что регистрируйте его последним.

## Длина данных

Telegram ограничивает данные кнопки 64 байтами. Буква кириллицы занимает два байта, так что в данные лучше класть id, а не названия. MAX разрешает до 1024 символов.

Если данные всё же длиннее 64 байт, matele заменит их для Telegram коротким ключом, а при нажатии вернёт исходное значение. Хендлер разницы не заметит.

Ключи хранятся в памяти и пропадают при перезапуске, а вместе с ними перестают работать длинные кнопки, отправленные до него. Чтобы они работали и после перезапуска, храните ключи в том же файле SQLite, что и состояния:

```python
from matele.fsm import SQLiteStorage
from matele.telegram import CallbackAliases, TelegramBot

storage = SQLiteStorage("bot.db")
dp = Dispatcher(storage=storage)
telegram = TelegramBot(TG_TOKEN, aliases=CallbackAliases(storage.aliases()))
```

Ключи, которые бот не отправлял в кнопках 60 дней, удаляются. Своё хранилище ключей, например в общей базе для нескольких процессов, можно сделать по протоколу `matele.telegram.AliasStore`: методы `save`, `get` и `purge`.

Проще всего до этого не доводить: если в данных только id и короткие коды, в 64 байта они помещаются с запасом.

## Ответ на нажатие

Пока бот не ответил на нажатие, кнопка показывает ожидание. matele отвечает сам после хендлера, но ответ можно сделать полезным:

```python
await ctx.answer("Сохранено")                         # короткое уведомление
await ctx.answer("Недостаточно прав", alert=True)     # окно, которое нужно закрыть
```

Учитывается только первый вызов `ctx.answer()` за событие, остальные ничего не делают.

В MAX нет окон с кнопкой «ОК». Там `alert=True` показывает то же короткое уведомление и дополнительно присылает текст человеку обычным сообщением в личный чат, чтобы важное не потерялось.

## Изменить сообщение с кнопкой

Обычно в ответ на нажатие меняют то сообщение, на котором кнопка была нажата. Так чат не заполняется новыми сообщениями. `ctx.edit()` меняет его текст и клавиатуру:

```python
@dp.callback(SetStatus)
async def set_status(ctx: Context, payload: SetStatus):
    await ctx.edit("Готово")              # кнопки исчезнут
    await ctx.edit("Готово", keyboard)    # кнопки заменятся
    await ctx.edit(None, keyboard)        # текст останется, заменятся только кнопки
```

Если клавиатуру не передать, она будет убрана. Это удобно для действий, которые выполняются один раз: после нажатия кнопки пропадают, и нажать второй раз нельзя.

Если весь интерфейс бота построен на кнопках, посмотрите на [меню в одном сообщении](menus.md): оно делает то же самое, но само решает, менять сообщение или отправить новое.

## Ссылки в кнопках

Мессенджеры строже относятся к ссылкам в кнопках, чем к ссылкам в тексте, и при ошибке отклоняют сообщение целиком:

- MAX не принимает ссылку на адрес, который он не считает публичным, например `localhost` или IP-адрес;
- Telegram принимает в кнопках только ссылки `http`, `https` и `tg`.

matele не даёт такому сообщению пропасть. В MAX неподходящая ссылка переносится из кнопки в текст сообщения. Если сообщение меняется без нового текста (`ctx.edit(None, keyboard)`), переносить ссылку некуда, и кнопка остаётся, но ничего не открывает, а в лог пишется предупреждение. В Telegram кнопка с такой ссылкой всегда остаётся и ничего не открывает.

Чаще всего с этим сталкиваются при разработке, когда в кнопку попадает адрес локального сервера.

## Права на кнопки

Данные кнопки приходят от приложения мессенджера, а не от ваших серверов. Модифицированное приложение может прислать в данных что угодно, например id чужого заказа. Поэтому проверяйте права в хендлере, а не полагайтесь на то, что кнопку видел только нужный человек:

```python
@dp.callback(SetStatus)
async def set_status(ctx: Context, payload: SetStatus):
    order = await orders.get(payload.order_id)
    if order.owner != (ctx.platform, ctx.user.id):
        await ctx.answer("Это не ваш заказ", alert=True)
        return
    ...
```

В группах это особенно важно: кнопки под сообщением бота может нажать любой участник.

### Подпись данных

Чтобы бот принимал только те кнопки, которые сам отправил, дайте ботам секрет:

```python
import os

max_bot = MaxBot(MAX_TOKEN, callback_secret=os.environ["CALLBACK_SECRET"])
telegram = TelegramBot(TG_TOKEN, callback_secret=os.environ["CALLBACK_SECRET"])
```

Секрет это любая длинная случайная строка. Сгенерировать её можно командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

Данные каждой кнопки уходят с подписью, а при нажатии подпись проверяется. Данные без верной подписи хендлер по классу не получит: они приходят как устаревшая кнопка, с `ctx.payload` равным `None`. Так нельзя подставить в данные id, которого бот этому человеку не показывал.

Что нужно знать о подписи:

- она не заменяет проверку прав. Человек по-прежнему может нажать любую настоящую кнопку, которую видел, в том числе чужую в группе;
- секрет должен быть одинаковым при каждом запуске. Если его сменить, все кнопки, отправленные раньше, перестанут работать;
- при включении подписи кнопки, отправленные до этого, тоже перестают работать, потому что подписи в них нет;
- подпись занимает 11 символов. Если данные из-за неё не помещаются в 64 байта Telegram, сработает обычная замена длинных данных ключом.
