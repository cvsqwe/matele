# Хендлеры и контекст

Хендлер это async-функция, которую matele вызывает, когда в мессенджере что-то произошло. Она получает один аргумент, `Context`: в нём само событие, данные человека и методы для ответа.

```python
from matele import Context, Dispatcher

dp = Dispatcher()


@dp.message()
async def any_message(ctx: Context):
    await ctx.reply("Получил ваше сообщение")
```

Декоратор говорит, на какие события хендлер реагирует. Сама функция может называться как угодно.

## Виды хендлеров

```python
@dp.command("start", "help")       # /start или /help
async def start(ctx: Context): ...


@dp.message()                      # любое сообщение: текст, файл, фото
async def any_message(ctx: Context): ...


@dp.callback(SetStatus)            # нажатие кнопки с данными SetStatus
async def set_status(ctx: Context, payload: SetStatus): ...


@dp.raw_callback()                 # любое нажатие, в том числе на устаревшие кнопки
async def any_button(ctx: Context): ...


@dp.chat_status()                  # человек заблокировал бота или вернулся
async def status(ctx: Context): ...


@dp.member_update()                # кто-то вошёл в группу или вышел из неё
async def member(ctx: Context): ...
```

Во все декораторы можно передать [фильтры](filters.md), а в первые четыре ещё и параметр `state`, который привязывает хендлер к шагу сценария (см. [Состояния](states.md)).

Про кнопки подробно рассказано в разделе [Кнопки](buttons.md), про события групп в разделе [Групповые чаты](groups.md).

## Команды

Команда это сообщение, которое начинается с `/`. В один декоратор можно передать несколько имён, тогда хендлер сработает на любое из них.

Имя команды не зависит от регистра: `/Start` и `/start` попадут в один хендлер. Всё, что написано после имени, лежит в `ctx.args`, а само имя в `ctx.command`:

```python
from matele import escape


@dp.command("remind")
async def remind(ctx: Context):
    # "/remind купить хлеб" -> ctx.command == "remind", ctx.args == "купить хлеб"
    if not ctx.args:
        await ctx.reply("Напишите, о чём напомнить: /remind купить хлеб")
        return
    await ctx.reply(f"Напомню: {escape(ctx.args)}")
```

Если после команды ничего нет, `ctx.args` равен `None`.

Команда распознаётся и в подписи к фото или файлу: если человек отправил картинку с подписью `/avatar`, сработает хендлер команды `avatar`, а сама картинка будет в `ctx.message.attachments`.

### Меню команд

У обоих мессенджеров есть меню команд: список, который открывается кнопкой рядом с полем ввода. matele собирает его из параметра `description`:

```python
@dp.command("orders", description="Мои заказы")
async def orders(ctx: Context): ...


@dp.command("debug")               # работает, но в меню не видна
async def debug(ctx: Context): ...
```

Меню публикуется при запуске бота, отдельно вызывать ничего не нужно. Команды идут в нём в порядке регистрации.

У команды с описанием есть ограничения, общие для двух мессенджеров: имя состоит из латинских букв в нижнем регистре, цифр и `_`, не длиннее 32 символов, а описание не длиннее 128 символов. Если их нарушить, ошибка будет сразу при запуске, а не когда-нибудь потом в логе. MAX показывает в меню не больше 32 команд.

Команды без описания в меню не попадают. Так удобно прятать служебные команды.

### Команды с адресом

В группах, где несколько ботов, команды пишут с адресом: `/help@my_bot`. Команду, адресованную другому боту, matele пропускает. Команды без адреса и с адресом самого бота обрабатываются как обычно.

## Контекст

Всё, что хендлер знает о событии, лежит в `ctx`.

Кто и откуда:

| Атрибут | Что в нём |
|---|---|
| `ctx.user` | кто прислал событие: `id`, `name`, `username`, `platform` |
| `ctx.platform` | `"max"` или `"telegram"`, удобно сравнивать с `matele.MAX` и `matele.TELEGRAM` |
| `ctx.chat_type` | `matele.PRIVATE` или `matele.GROUP` |
| `ctx.chat_id` | id группы, в личном чате `None` |
| `ctx.bot` | бот, через который пришло событие |

`ctx.user.name` и `ctx.user.username` могут быть `None`: не у всех есть имя пользователя, а иногда мессенджер присылает только id.

Что произошло:

| Атрибут | Что в нём |
|---|---|
| `ctx.event` | само событие: `Message`, `CallbackQuery`, `ChatStatus` или `ChatMemberUpdate` |
| `ctx.text` | текст сообщения, для остальных событий пустая строка |
| `ctx.message` | пришедшее сообщение или сообщение, на котором нажали кнопку |
| `ctx.command`, `ctx.args` | имя команды и текст после неё |
| `ctx.callback` | нажатие кнопки целиком, сырые данные в `ctx.callback.data` |
| `ctx.payload` | разобранные данные нажатой кнопки |
| `ctx.is_callback` | `True`, если событие это нажатие кнопки |
| `ctx.chat_status` | событие блокировки бота, для остальных событий `None` |
| `ctx.member_update` | событие входа или выхода из группы, для остальных `None` |
| `ctx.match` | результат фильтра `Regex` |

Состояние и свои данные:

| Атрибут | Что в нём |
|---|---|
| `ctx.state` | состояние разговора, см. [Состояния](states.md) |
| `ctx.data` | словарь для данных, которые middleware передаёт хендлеру |

## Как ответить

| Метод | Что делает |
|---|---|
| `await ctx.reply(text, keyboard)` | новое сообщение туда, откуда пришло событие |
| `await ctx.reply_file(path, kind="image")` | фото, видео, аудио или файл |
| `await ctx.send_private(text)` | сообщение человеку в личку, даже из группы |
| `await ctx.edit(text, keyboard)` | изменить сообщение, на котором нажали кнопку |
| `await ctx.show(text, keyboard)` | показать экран [меню в одном сообщении](menus.md) |
| `await ctx.answer(text)` | всплывающее уведомление в ответ на нажатие кнопки |
| `await ctx.delete()` | удалить пришедшее сообщение или сообщение с кнопкой |
| `async with ctx.typing():` | показывать статус «печатает…», пока выполняется блок |

`ctx.reply()` возвращает отправленное сообщение. Его `message_id` можно сохранить, чтобы позже изменить или удалить это сообщение:

```python
@dp.command("report")
async def report(ctx: Context):
    sent = await ctx.reply("Считаю...")
    total = await count_everything()
    await ctx.bot.edit_message(sent.message_id, f"Готово: {total}")
```

`ctx.reply(text, quote=True)` отправляет сообщение ответом на сообщение человека.

Текст всех сообщений отправляется как HTML. Всё, что пришло снаружи (имя человека, его текст, аргументы команды), перед вставкой в сообщение пропускайте через `escape()`. Подробнее в разделе [Файлы и форматирование](files.md#форматирование-текста).

`ctx.edit()` и `ctx.answer()` имеют смысл только для нажатия кнопки. `ctx.answer()` на другом событии ничего не делает, а `ctx.edit()` бросает `RuntimeError`: редактировать нечего.

## Порядок хендлеров

Для каждого события вызывается не больше одного хендлера: первый, у которого подошли команда, состояние и фильтры. Хендлеры проверяются в таком порядке:

1. команды;
2. хендлеры, привязанные к состоянию (`state=...`);
3. все остальные.

Внутри каждой группы хендлеры проверяются в порядке регистрации.

Такой порядок выбран не случайно. Команды идут первыми, чтобы `/cancel` срабатывал посреди любого сценария, даже когда бот ждёт от человека ввода. Хендлеры состояний идут раньше общих, чтобы ответ на вопрос анкеты не перехватил `@dp.message()`, даже если тот зарегистрирован раньше.

```python
@dp.message()                          # группа 3: всё, что не подошло выше
async def fallback(ctx: Context):
    await ctx.reply("Не понял. Список команд: /help")


@dp.message(state=Signup.name)         # группа 2: проверяется раньше fallback
async def got_name(ctx: Context): ...


@dp.command("cancel")                  # группа 1: проверяется раньше всех
async def cancel(ctx: Context): ...
```

Если не подошёл ни один хендлер, событие просто пропускается. Middleware при этом всё равно отрабатывает.

Хендлеры нужно регистрировать до запуска бота. После первого события список закрывается, и попытка добавить хендлер закончится ошибкой `RuntimeError`.

## Человек заблокировал бота

```python
@dp.chat_status()
async def status(ctx: Context):
    if ctx.chat_status.reachable:
        await db.mark_active(ctx.platform, ctx.user.id)
    else:
        await db.mark_blocked(ctx.platform, ctx.user.id)
```

Событие приходит, когда человек заблокировал бота (`reachable` равен `False`) или снова его запустил (`True`). Написать ему в ответ на блокировку уже нельзя, а вот отметить у себя, чтобы не слать ему рассылки, стоит.

Событие касается только личного чата с ботом. О том, что бота удалили из группы, сообщает `@dp.member_update()`.
