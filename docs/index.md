# matele

matele это фреймворк на Python для ботов, которые работают сразу в MAX и Telegram. Вы пишете хендлеры один раз, а бот отвечает людям в обоих мессенджерах из одного процесса.

```python
from matele import Context, Dispatcher, escape
from matele.max import MaxBot
from matele.telegram import TelegramBot

dp = Dispatcher()


@dp.command("start", description="Начать")
async def start(ctx: Context):
    await ctx.reply(f"Привет, {escape(ctx.user.name)}!")


@dp.message()
async def echo(ctx: Context):
    await ctx.reply(escape(ctx.text) or "Это не текст")


dp.run_polling(MaxBot(MAX_TOKEN), TelegramBot(TG_TOKEN))
```

Это полный бот. `Dispatcher` хранит хендлеры, `MaxBot` и `TelegramBot` подключаются к мессенджерам, а `run_polling` забирает события из обоих и раздаёт их хендлерам. Если второй мессенджер не нужен, передайте в `run_polling` только один бот: код хендлеров от этого не меняется.

!!! warning "Ранняя версия"
    До версии 1.0 API может меняться, каждое ломающее изменение записывается в [список изменений](changelog.md).

## Зачем это нужно

MAX и Telegram похожи снаружи, но их Bot API устроены по-разному, и бот, написанный для одного, приходится переписывать для другого. Вот несколько различий, с которыми вы столкнётесь уже в первый день:

- Чтобы изменить сообщение, Telegram требует id чата и id сообщения, а MAX только id сообщения.
- Данные кнопки в Telegram не длиннее 64 байт, в MAX до 1024 символов.
- Значение из ссылки на запуск бота Telegram присылает как текст `/start promo`, а MAX как отдельное событие.
- О том, что человек заблокировал бота, мессенджеры сообщают разными событиями.
- MAX отклоняет сообщение целиком, если в кнопке ссылка на адрес, который он не считает публичным. Telegram делает то же самое со ссылками не по `http`, `https` или `tg`.

matele приводит всё это к одному виду. Хендлер получает `Context` с одинаковыми полями и методами, откуда бы ни пришло событие, а различия остаются внутри `MaxBot` и `TelegramBot`. Когда нужна возможность, которая есть только в одном мессенджере, до его API можно добраться напрямую через `ctx.bot.api`.

## Что умеет

Обработка событий:

- команды, сообщения, нажатия кнопок, события групп и блокировки бота приходят в один и тот же `Context`;
- фильтры, роутеры, middleware и обработчики ошибок, как в привычных фреймворках для ботов;
- состояния для сценариев из нескольких шагов, с хранением в памяти, SQLite или Redis.

Интерфейс бота:

- кнопки под сообщением с типизированными данными: в хендлер приходит объект с полями, а не строка, которую надо разбирать;
- меню, которое живёт в одном сообщении и не засоряет чат;
- меню команд мессенджера, которое собирается из описаний команд;
- фото, видео, аудио и файлы, ответы на сообщения, статус «печатает…»;
- мини-приложения: кнопка открытия и проверка подписи `initData`.

Запуск и надёжность:

- long polling и вебхуки, каждый мессенджер опрашивается независимо: если один недоступен, второй продолжает работать;
- рассылки во все мессенджеры человека с ограничением скорости и повторами;
- остановка без потери начатой работы, ограничение нагрузки, доставка событий «минимум один раз» по желанию;
- типизированный клиент ко всему MAX Bot API и доступ к любому методу Telegram Bot API;
- `FakeBot` для тестов без сети и токенов.

## Установка

Нужен Python 3.11 или новее.

```bash
pip install matele
```

Вебхуки и хранение состояний в Redis требуют дополнительных пакетов, они ставятся отдельно. Подробности на странице [Первый бот](first-bot.md#установка).
