# matele

matele это фреймворк на Python для ботов, которые работают сразу в MAX и Telegram. Хендлеры пишутся один раз, а различия между мессенджерами matele берёт на себя: как устроены идентификаторы сообщений, какие ограничения у кнопок, как приходят ссылки на запуск бота, что умеет каждый мессенджер в группах.

```python
from matele import Context, Dispatcher
from matele.max import MaxBot
from matele.telegram import TelegramBot

dp = Dispatcher()


@dp.command("start", description="Начать")
async def start(ctx: Context):
    await ctx.reply(f"Привет, {ctx.user.name}!")


@dp.message()
async def echo(ctx: Context):
    await ctx.reply(ctx.text or "Это не текст")


dp.run_polling(MaxBot(MAX_TOKEN), TelegramBot(TG_TOKEN))
```

Один процесс, один `Dispatcher`, два бота. Если второй мессенджер не нужен, передайте в `run_polling` только один из них.

!!! warning "Ранняя версия"
    Проект ещё не вышел в версии 0.1 и не опубликован на PyPI. API может меняться, каждое ломающее изменение записывается в [список изменений](changelog.md).

## Что внутри

- Команды, сообщения, кнопки и события групп разбираются в один и тот же `Context`, где бы они ни случились.
- Данные кнопок описываются классами. В хендлер приходит готовый объект с типами, а длинные данные для Telegram matele сам укорачивает.
- Состояния для многошаговых сценариев с хранением в памяти, SQLite или Redis.
- Меню, которое живёт в одном сообщении и не засоряет чат.
- Фото, видео, аудио и файлы: большие уходят потоком и не читаются в память целиком. Ответы на сообщения, статус «печатает…».
- Long polling и вебхуки. Каждый мессенджер опрашивается независимо: если один недоступен, второй продолжает работать.
- Мини-приложения с проверкой подписи `initData` для обоих мессенджеров.
- Рассылки во все мессенджеры человека с ограничением скорости и повторами.
- Типизированный клиент ко всему MAX Bot API и доступ к любому методу Telegram Bot API.
- `FakeBot` для тестов без сети и токенов.

## С чего начать

Если вы раньше не писали ботов, начните с [первого бота](first-bot.md): там по шагам описано, где взять токены и как запустить бота в обоих мессенджерах. Если опыт есть, а нужно что-то конкретное, разделы руководства можно читать в любом порядке.

Если вы писали ботов на aiogram, многое будет знакомо: роутеры, фильтры, middleware и состояния устроены похоже. Главное отличие в том, что хендлер получает не объект Telegram, а общий для двух мессенджеров `Context`.
