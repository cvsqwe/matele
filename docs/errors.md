# Ошибки

В боте ошибки бывают двух видов. Первые это ошибки в вашем коде: хендлер упал с исключением. Вторые это отказы мессенджера: он не принял сообщение, потому что человек заблокировал бота, или вообще недоступен. На этой странице про то, что делает matele в обоих случаях и что стоит сделать вам.

## Когда падает хендлер

Исключение в хендлере, фильтре или middleware не останавливает бота. Оно касается только одного события, остальные обрабатываются дальше. Если своего обработчика нет, исключение пишется в лог вместе с описанием события: его тип, мессенджер, id человека и чата. Текста сообщения в логе нет.

Чтобы человек не оставался без ответа, зарегистрируйте обработчик ошибок:

```python
import logging

from matele import Context


@dp.on_error
async def on_error(ctx: Context, exc: Exception):
    logging.exception("Ошибка в хендлере", exc_info=exc)
    if ctx.is_callback:
        await ctx.answer("Что-то пошло не так", alert=True)
    else:
        await ctx.reply("Что-то пошло не так, попробуйте ещё раз")
```

Обработчик получает тот же контекст, что и хендлер, поэтому может ответить человеку. Обработчиков может быть несколько, вызываются все по порядку. Если упал сам обработчик, это записывается в лог и на остальное не влияет.

Вот что matele делает после упавшего хендлера сам:

- отвечает на нажатие кнопки, если хендлер не успел. Иначе кнопка у человека продолжала бы показывать ожидание;
- сохраняет состояние разговора, если хендлер успел его изменить.

Второе важно помнить при проектировании сценариев. Если хендлер сначала вызвал `ctx.state.set(...)`, а потом упал, человек окажется на новом шаге. Поэтому переводите состояние в конце хендлера, когда всё, что могло не получиться, уже получилось:

```python
@dp.message(state=Order.address)
async def got_address(ctx: Context):
    order = await orders.create(ctx.user.id, address=ctx.text)   # может упасть
    ctx.state.update(order_id=order.id)
    ctx.state.set(Order.payment)                                  # только после успеха
    await ctx.reply("Адрес сохранён. Как будете платить?")
```

## Ошибки мессенджера

Когда мессенджер отказывается выполнить запрос, методы бота бросают `BotApiError`. У исключения четыре поля:

| Поле | Что в нём |
|---|---|
| `status_code` | HTTP-код ответа, например 400 или 403 |
| `code` | код ошибки: в MAX вроде `chat.denied`, в Telegram имя метода |
| `message` | текст ошибки от мессенджера |
| `platform` | `"max"` или `"telegram"` |

У него есть три наследника.

`BotForbiddenError` значит, что человеку нельзя написать: он заблокировал бота или ни разу его не запускал. Повторять бессмысленно, пока человек сам не вернётся.

`BotUnavailableError` значит, что до мессенджера не удалось достучаться: проблема с сетью или сам мессенджер недоступен. Запрос можно повторить позже.

`InvalidTokenError` значит, что мессенджер не принял токен бота при запуске (ответ 401, а у Telegram 404 на токен неправильного вида). Его бросает `run_polling()`: polling останавливается сразу, во всех мессенджерах, потому что это ошибка в настройках, а не сбой, который пройдёт сам.

```python
from matele import BotApiError, BotForbiddenError, BotUnavailableError

try:
    await bot.send_message("Ваш заказ готов", user_id=user_id)
except BotForbiddenError:
    await db.mark_blocked(bot.platform, user_id)
except BotUnavailableError:
    await queue.retry_later(user_id)
except BotApiError as exc:
    logging.error("Мессенджер отказал: %s", exc)
```

### Можно ли написать человеку

Мессенджеры сообщают о том, что человеку нельзя написать, по-разному: разными кодами и текстами. Функция `is_unreachable(exc)` знает их все и отвечает на один вопрос: значит ли эта ошибка, что писать этому человеку сейчас бесполезно.

```python
from matele import BotApiError, is_unreachable

try:
    await ctx.send_private("Ваш код: 4821")
except BotApiError as exc:
    if not is_unreachable(exc):
        raise
    await ctx.reply("Сначала откройте личный чат с ботом")
```

Используйте её там, где вы хотите отличить «человек недоступен» от всех остальных ошибок.

### Что matele повторяет сам

Некоторые отказы временные, и matele справляется с ними без вашего участия:

- ответ 429 «слишком много запросов»: запрос повторяется после паузы, которую назвал мессенджер. На время паузы ждут и все остальные запросы к этому мессенджеру, чтобы не усугублять;
- ответы 502, 503 и 504: запрос повторяется несколько раз с растущей паузой;
- файл в MAX ещё не обработан после загрузки: отправка повторяется, пока MAX его не примет.

Если повторы не помогли, вы получите `BotApiError`.

### Что matele прощает

Есть ошибки, которые ошибками по сути не являются, и matele не превращает их в исключения:

- Telegram отказался менять сообщение, потому что новый текст совпадает со старым;
- Telegram не принял ответ на нажатие кнопки, потому что нажатие слишком старое;
- текст сообщения не разобрался как HTML: Telegram получит его повторно простым текстом, чтобы сообщение не пропало.

## Когда мессенджер недоступен

Если до мессенджера не удалось достучаться два раза подряд, matele считает, что он недоступен, и следующие 30 секунд запросы к нему сразу заканчиваются `BotUnavailableError`, не дожидаясь таймаута. Без этого при сбое мессенджера каждый хендлер висел бы по полминуты на своём запросе, и бот выглядел бы зависшим целиком.

Считаются только сбои соединения. Один медленный ответ или зависшая загрузка большого файла остальным запросам не мешают.

Мессенджеры независимы друг от друга: пока недоступен один, бот во втором работает как обычно. Long polling продолжает пробовать подключиться, и как только мессенджер ответит, запросы снова пойдут.

Для хендлера это значит, что `ctx.reply()` во время сбоя быстро бросит `BotUnavailableError`. Ответить человеку в этот момент всё равно нельзя, так что обычно достаточно обработчика ошибок, который запишет это в лог.

## Логи

matele пишет в стандартный модуль `logging`, все его логгеры начинаются с `matele`. Чтобы видеть, что происходит, достаточно настроить логирование в начале программы:

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(name)s: %(message)s")
```

Что на каком уровне пишется:

| Уровень | Что пишется |
|---|---|
| `ERROR` | исключения в хендлерах без обработчика, сбои хранилища состояний |
| `WARNING` | polling не может подключиться, запрос на вебхук с неверным секретом, не доставлено сообщение рассылки |
| `INFO` | запуск polling и вебхуков, повторы запросов, остановка |
| `DEBUG` | события без хендлера, устаревшие кнопки, пропущенные события |

Уровень `DEBUG` полезен при разработке, когда бот молчит и непонятно почему: в логе будет видно, что событие пришло, но ни один хендлер его не взял.

```python
logging.getLogger("matele").setLevel(logging.DEBUG)
```

Токен бота в логи не попадает. В адресах Telegram Bot API токен есть, и библиотека `httpx` пишет адреса запросов в лог, поэтому matele вырезает токен из её записей.
