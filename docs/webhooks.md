# Вебхуки

При long polling бот сам постоянно спрашивает мессенджер о новых событиях. С вебхуками наоборот: мессенджер отправляет каждое событие HTTP-запросом на ваш сервер. Вебхуки нужны, когда бот работает рядом с веб-приложением или когда событий много.

Для начала и для небольших ботов polling проще: ему не нужен ни домен, ни сертификат.

## Запуск

Поставьте `matele[webhook]`, чтобы был uvicorn:

```python
from matele import Dispatcher
from matele.max import MaxBot
from matele.telegram import TelegramBot
from matele.webhook import Webhook

dp = Dispatcher()
# ... хендлеры ...

webhook = Webhook(dp, base_url="https://bot.example.com")
webhook.add(MaxBot(MAX_TOKEN), "/max")
webhook.add(TelegramBot(TG_TOKEN), "/telegram")

if __name__ == "__main__":
    webhook.run(port=8080)
```

При запуске `Webhook` сам регистрирует адреса `https://bot.example.com/max` и `https://bot.example.com/telegram` в мессенджерах и публикует меню команд. При остановке он ждёт, пока доработают начатые хендлеры, и закрывает ботов и хранилище.

## Требования мессенджеров

Нужен публичный адрес HTTPS с настоящим сертификатом. MAX принимает только порт 443, Telegram порты 443, 80, 88 и 8443. Обычно бот слушает локальный порт, а перед ним стоит nginx или Caddy, который принимает HTTPS на 443 и передаёт запросы боту:

```nginx
server {
    listen 443 ssl;
    server_name bot.example.com;
    # ssl_certificate ... (например, от Let's Encrypt)

    location / {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

Для проверки на своём компьютере подойдёт туннель вроде cloudflared или ngrok: он даёт временный HTTPS-адрес, который можно передать в `base_url`.

## Безопасность

Адрес вебхука можно угадать, поэтому `Webhook` при регистрации передаёт мессенджерам случайный секрет и проверяет его в каждом запросе. Запросы без секрета получают ответ 403 и не обрабатываются.

Секрет генерируется при каждом запуске. Если вы запускаете несколько процессов за одним адресом, задайте общий секрет сами: `Webhook(dp, base_url=..., secret=os.environ["WEBHOOK_SECRET"])`. Он должен состоять из 5-256 символов: латинские буквы, цифры, `_` и `-`.

## Как обрабатываются запросы

`Webhook` сразу отвечает мессенджеру 200, а событие обрабатывает в фоне. Иначе медленный хендлер заставил бы мессенджер решить, что сервер не ответил, и прислать событие ещё раз. События одного человека, как и при polling, обрабатываются по очереди.

Если хендлеры не успевают и в очереди накопилось `max_pending` событий (по умолчанию 1000), новые запросы получают ответ 503, и мессенджер пришлёт их позже. Так всплеск событий не съедает всю память процесса. При polling то же самое делает параметр `run_polling(..., concurrency=100)`: одновременно обрабатывается не больше стольких событий одного мессенджера, остальные ждут на его стороне.

Если событие не удалось разобрать, оно записывается в лог, а мессенджер всё равно получает 200, чтобы не присылать сломанное событие бесконечно.

## Другие ASGI-серверы и фреймворки

`Webhook` это обычное ASGI-приложение, поэтому его можно запустить любым ASGI-сервером:

```bash
uvicorn bot:webhook --host 127.0.0.1 --port 8080
```

Если у вас уже есть приложение на Starlette или FastAPI, вебхук можно подключить внутрь него:

```python
from fastapi import FastAPI

app = FastAPI()
app.mount("/hooks", webhook)  # адреса станут /hooks/max и /hooks/telegram
```

При подключении через `mount` FastAPI не передаёт вебхуку события запуска и остановки, поэтому вызовите `await webhook.startup()` и `await webhook.shutdown()` в lifespan своего приложения. `base_url` в этом случае включает префикс: `https://bot.example.com/hooks`.

В любом другом фреймворке можно вызвать обработку вручную. `handle()` возвращает HTTP-код, которым нужно ответить:

```python
status = await webhook.handle("/telegram", request.headers, await request.body())
```

## Переход обратно на polling

Telegram не отдаёт события через polling, пока установлен вебхук. Сам matele вебхук не удаляет: он может принадлежать работающему боту, и локальный запуск с тем же токеном оставил бы его без событий. Вместо этого polling пишет в лог предупреждение с адресом вебхука и ждёт. Удалите вебхук сами (`await bot.delete_webhook()`) или разрешите это явно: `TelegramBot(token, replace_webhook=True)`. MAX тоже перестаёт отдавать события через polling, если есть подписка на вебхук. Её matele не удаляет, а пишет в лог предупреждение с адресом. Удалить вебхук при остановке сервера можно параметром `Webhook(..., delete_on_shutdown=True)`.
