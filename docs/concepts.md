# Как устроен matele

На этой странице нет ничего, что нужно выучить, чтобы написать бота. Она объясняет, из каких частей состоит matele и что происходит между сообщением человека и ответом бота. Когда поведение бота покажется неочевидным, ответ, скорее всего, здесь.

## Части

В боте на matele участвуют четыре вещи.

Бот мессенджера (`MaxBot`, `TelegramBot`) умеет разговаривать с одним мессенджером. Он получает события в формате этого мессенджера и превращает их в общие события matele, а вызовы вроде «отправь сообщение» превращает в запросы к API мессенджера. В документации и в коде такие объекты ещё называются транспортами.

Событие это то, что произошло в мессенджере: человек написал сообщение, нажал кнопку, заблокировал бота, вошёл в группу. Событий четыре вида, и они одинаковые для обоих мессенджеров.

Диспетчер (`Dispatcher`) хранит хендлеры и для каждого события выбирает, какой из них вызвать.

Контекст (`Context`) это объект, который получает хендлер. В нём само событие, состояние разговора с человеком и методы для ответа.

```python
from matele import Context, Dispatcher
from matele.max import MaxBot
from matele.telegram import TelegramBot

dp = Dispatcher()                       # диспетчер


@dp.message()
async def any_message(ctx: Context):    # хендлер получает контекст
    await ctx.reply("Получил")          # ответ уходит в тот же мессенджер


dp.run_polling(MaxBot(MAX_TOKEN), TelegramBot(TG_TOKEN))   # два транспорта
```

## События

| Событие | Когда приходит | Декоратор |
|---|---|---|
| `Message` | человек прислал сообщение: текст, команду, файл | `@dp.message()`, `@dp.command()` |
| `CallbackQuery` | человек нажал кнопку под сообщением бота | `@dp.callback()`, `@dp.raw_callback()` |
| `ChatStatus` | человек заблокировал бота или снова его запустил | `@dp.chat_status()` |
| `ChatMemberUpdate` | кто-то вошёл в группу или вышел, бота добавили или удалили | `@dp.member_update()` |

У каждого события есть `from_user` (кто это сделал) и `bot` (через какой транспорт оно пришло). Поэтому ответ всегда уходит в тот же мессенджер, откуда пришло событие: `ctx.reply()` вызывает метод того бота, который лежит в событии.

Некоторые события matele собирает сам, чтобы мессенджеры выглядели одинаково. Например, MAX сообщает о запуске бота по ссылке отдельным событием, а matele превращает его в обычное сообщение `/start значение`, как это делает Telegram.

## Путь одного события

Вот что происходит, когда человек пишет боту.

1. Транспорт получает событие от мессенджера, через long polling или вебхук, и переводит его в общий вид.
2. Диспетчер загружает из хранилища состояние разговора с этим человеком.
3. Создаётся `Context`. Если это команда, в нём уже разобраны её имя и аргументы. Если нажатие кнопки, разобраны её данные.
4. Событие проходит через middleware в порядке их регистрации.
5. Диспетчер ищет первый хендлер, которому подходят команда, состояние и фильтры, и вызывает его. Для одного события вызывается не больше одного хендлера.
6. Если хендлер или middleware упали с исключением, вызываются обработчики ошибок. Без них исключение пишется в лог.
7. Если это было нажатие кнопки и хендлер на него не ответил, диспетчер отвечает сам, чтобы кнопка не крутилась бесконечно.
8. Если состояние изменилось, оно сохраняется в хранилище. Это происходит и тогда, когда хендлер упал.

Из этого порядка следует несколько полезных свойств.

Исключение в хендлере не останавливает бота. Оно касается только одного события, остальные обрабатываются дальше.

Состояние внутри хендлера это обычный объект в памяти. `ctx.state.set()` и `ctx.state.update()` ничего не пишут в базу и не требуют `await`. Запись происходит один раз, после хендлера.

Middleware видит и те события, для которых не нашлось хендлера. Это удобно для логирования и для блокировки нежелательных пользователей.

## Очерёдность

События разных людей обрабатываются одновременно: пока один хендлер ждёт ответа от базы или мессенджера, работают хендлеры других людей. Медленный хендлер не задерживает остальных.

События одного человека обрабатываются по очереди. Если человек быстро отправил два сообщения, второе подождёт, пока не закончится хендлер первого. Иначе оба хендлера прочитали бы одно и то же состояние, и второй затёр бы то, что сохранил первый. В группе очередь своя у каждой пары «человек и группа».

Каждый мессенджер опрашивается независимо. Если MAX недоступен, бот в Telegram этого не заметит, и наоборот.

## Кто есть кто

У человека в MAX и в Telegram разные id. Более того, id человека в одном мессенджере может совпасть с id другого человека во втором. Поэтому человека в matele определяет пара: мессенджер и id.

```python
key = (ctx.platform, ctx.user.id)    # ("max", 123) или ("telegram", 123): это разные люди
```

Храните в своей базе именно пару. Если нужно знать, что аккаунт в MAX и аккаунт в Telegram принадлежат одному человеку, свяжите их сами, например через [ссылку на запуск](first-bot.md#ссылки-на-запуск) с одноразовым кодом.

Состояние разговора хранится отдельно для каждой такой пары, а в группе ещё и отдельно для каждой группы.

## Идентификаторы сообщений

`message_id` в matele это строка, смысл которой знает только тот мессенджер, откуда она пришла. В MAX это id сообщения как есть. В Telegram это `"chat_id:message_id"`, потому что Telegram для изменения и удаления сообщения требует оба числа.

На практике это значит одно: `message_id` можно сохранять и передавать обратно в методы того же бота, но не нужно разбирать его самому или передавать боту другого мессенджера. Если разобрать всё же нужно, для прямого вызова Telegram Bot API есть `TelegramBot.split_id()`.

## Что общее, а что нет

Общий слой matele покрывает то, что есть в обоих мессенджерах и работает одинаково: сообщения, кнопки, файлы, группы, состояния. Этого хватает для большинства ботов.

У каждого мессенджера есть и своё: закреплённые сообщения, права администраторов, опросы, платежи, стикеры. Для этого у каждого бота есть свойство `api` с клиентом API его мессенджера. Как им пользоваться, рассказано в разделе [API мессенджеров](platform-api.md).

Там, где мессенджеры ведут себя по-разному, а matele не может это скрыть, документация говорит об этом прямо. Например, окно с кнопкой «ОК» в ответ на нажатие кнопки есть только в Telegram, и в MAX matele заменяет его уведомлением и обычным сообщением.
