# Рассылки

Хендлеры отвечают на то, что сделал человек. Но бот пишет и сам: напоминает о записи, сообщает, что заказ готов, рассылает новости подписчикам. Для таких сообщений есть `Hub`.

`Hub` знает обо всех ботах сразу и умеет три вещи: отправить сообщение человеку во все мессенджеры, где он есть, разослать сообщение многим людям с той скоростью, которую разрешают мессенджеры, и не споткнуться о тех, кто бота заблокировал.

```python
from matele.hub import Hub
from matele.max import MaxBot
from matele.telegram import TelegramBot

max_bot, telegram_bot = MaxBot(MAX_TOKEN), TelegramBot(TG_TOKEN)
hub = Hub(max_bot, telegram_bot)
```

`Hub` работает где угодно: в хендлере, в планировщике, в веб-админке. Запущенный `Dispatcher` ему не нужен. Если бот уже работает через `run_polling` или вебхуки, передайте в `Hub` те же объекты ботов, а не создавайте новые.

## Кому можно писать

Бот может написать только тому, кто сам открывал с ним чат и не заблокировал его. Это правило мессенджеров, обойти его нельзя.

Поэтому список получателей бот собирает сам, по мере того как люди ему пишут. Самый простой способ: сохранять человека при команде `/start`.

```python
@dp.command("start")
async def start(ctx: Context):
    await db.save_subscriber(ctx.platform, ctx.user.id)
    await ctx.reply("Вы подписаны на новости")
```

Сохраняйте пару из мессенджера и id: id в MAX и Telegram независимы.

## Одному человеку

Человек описывается словарём «мессенджер: id». Если он есть в обоих мессенджерах, сообщение придёт в оба:

```python
import logging

deliveries = await hub.send({"max": 123, "telegram": 456}, "Заказ готов")
for d in deliveries:
    if not d.ok:
        logging.warning("%s: не доставлено: %s", d.platform, d.error)
```

Если человек есть только в одном мессенджере, в словаре будет один ключ: `{"telegram": 456}`. Мессенджеры, для которых в `Hub` нет бота, пропускаются.

`send` не бросает исключений. Результат по каждому мессенджеру лежит в `Delivery`:

| Поле | Что в нём |
|---|---|
| `platform` | мессенджер |
| `user_id` | id человека в нём |
| `ok` | `True`, если сообщение доставлено |
| `message` | отправленное сообщение, если доставлено |
| `error` | исключение, если не доставлено |

Отправка в мессенджеры идёт одновременно, и сбой в одном не мешает доставке во второй.

### Один человек в двух мессенджерах

Чтобы писать человеку в оба мессенджера, нужно знать, что аккаунт в MAX и аккаунт в Telegram принадлежат одному человеку. Сами мессенджеры этого не сообщают, связать аккаунты можно только с участием человека.

Обычный способ: бот в одном мессенджере выдаёт одноразовый код в виде [ссылки на запуск](first-bot.md#ссылки-на-запуск) бота во втором. Человек переходит по ссылке, второй бот получает код в `ctx.args` и связывает аккаунты.

```python
@dp.command("link")
async def link(ctx: Context):
    code = await db.create_link_code(ctx.platform, ctx.user.id)
    other = telegram_bot if ctx.platform == "max" else max_bot
    await ctx.reply(f"Откройте бота во втором мессенджере: {other.deep_link(other.me.username, code)}")


@dp.command("start")
async def start(ctx: Context):
    if ctx.args and (owner := await db.take_link_code(ctx.args)):
        await db.link_accounts(owner, (ctx.platform, ctx.user.id))
        await ctx.reply("Аккаунты связаны")
        return
    await ctx.reply("Привет!")
```

## Многим людям

```python
import sqlite3

conn = sqlite3.connect("bot.db")


def subscribers():
    rows = conn.execute("SELECT max_id, telegram_id FROM subscribers WHERE NOT blocked")
    for max_id, telegram_id in rows:
        accounts = {}
        if max_id:
            accounts["max"] = max_id
        if telegram_id:
            accounts["telegram"] = telegram_id
        yield accounts


report = await hub.broadcast(subscribers(), "Мы открылись!")
print(report.people, report.reached, report.delivered, report.failed)
```

Получателей можно передать списком или генератором. Генератор читается постепенно, по мере отправки, так что список из миллиона человек не придётся целиком держать в памяти.

`broadcast` ждёт, пока рассылка закончится, и возвращает отчёт `BroadcastReport`:

| Поле | Что в нём |
|---|---|
| `people` | скольким людям пытались отправить |
| `reached` | сколько получили сообщение хотя бы в одном мессенджере |
| `delivered` | сколько отправок удалось, считая каждый мессенджер отдельно |
| `failed` | сколько отправок не удалось |
| `unreachable` | список `(мессенджер, id)` тех, кто заблокировал бота или ни разу его не запускал |
| `deliveries` | все `Delivery` подряд |

Разница между `reached` и `delivered`: человек с двумя мессенджерами, получивший сообщение в обоих, считается один раз в `reached` и два раза в `delivered`.

В отчёте рассылки у `Delivery` нет поля `message`: хранится только результат, чтобы отчёт о большой рассылке не занимал много памяти.

### Сколько это займёт

Скорость рассылки ограничена мессенджерами, а не вашим сервером. При 25 сообщениях в секунду 10 тысяч человек получат сообщение примерно за 7 минут, 100 тысяч за час с небольшим.

Рассылка не мешает боту отвечать людям: хендлеры работают как обычно. Но она делит с ними общий лимит мессенджера, поэтому большую рассылку разумно запускать, когда бот не слишком занят.

Из хендлера рассылку лучше запускать фоновой задачей. Иначе хендлер будет ждать её конца, а все следующие сообщения этого администратора будут ждать хендлер:

```python
import asyncio

background: set[asyncio.Task] = set()


@dp.command("announce", is_admin)
async def announce(ctx: Context):
    if not ctx.args:
        await ctx.reply("Напишите текст после команды: /announce Мы открылись!")
        return
    task = asyncio.create_task(hub.broadcast(subscribers(), ctx.args))
    background.add(task)
    task.add_done_callback(background.discard)
    await ctx.reply("Рассылка запущена")
```

Множество `background` нужно, чтобы задача не была удалена сборщиком мусора до завершения.

## Продолжить после перезапуска

Большая рассылка идёт долго, и процесс за это время может перезапуститься: выкатили новую версию, перезагрузился сервер. Чтобы не начинать сначала и не писать людям дважды, отмечайте каждого получателя в `on_sent`:

```python
async def mark_sent(accounts, deliveries):
    conn.execute("UPDATE subscribers SET sent_campaign = ? WHERE max_id = ?", (CAMPAIGN, accounts.get("max")))
    conn.commit()


report = await hub.broadcast(subscribers(), "Мы открылись!", on_sent=mark_sent)
```

`on_sent` вызывается после каждого человека и получает его аккаунты и список `Delivery`. При повторном запуске выбирайте из базы только тех, у кого отметки ещё нет.

Если процесс упал между отправкой и отметкой, этот человек получит сообщение второй раз, но только он. Если `on_sent` упал с ошибкой, она запишется в лог, а рассылка продолжится.

## Скорость и сбои

Мессенджеры ограничивают, сколько сообщений бот может отправить в секунду, примерно 30 и в MAX, и в Telegram. `Hub` по умолчанию отправляет не больше 25 сообщений в секунду в каждый мессенджер. Скорость можно задать для всех мессенджеров или для каждого отдельно:

```python
hub = Hub(max_bot, telegram_bot, rate={"max": 20, "telegram": 25})
```

Ограничение действует на весь `Hub`: и на рассылки, и на отдельные `send`. Поэтому создавайте один `Hub` на программу. Если через одного бота отправляют несколько процессов, разделите лимит между ними, чтобы в сумме не превысить ограничение.

`concurrency` (по умолчанию 10) у `broadcast` ограничивает, скольким людям сообщение отправляется одновременно. Общую скорость задаёт `rate`, а не `concurrency`.

Что происходит при сбоях:

- мессенджер ответил «слишком часто»: все отправки в него ставятся на паузу, которую он назвал, а потом продолжаются;
- мессенджер ненадолго пропал из сети: `Hub` подождёт и повторит отправку. Повтор бывает, только если запрос точно не ушёл. Если ответ просто не пришёл вовремя, сообщение могло дойти, и `Hub` не отправляет его второй раз, а записывает ошибку в отчёт;
- мессенджер недоступен долго: отправки в него сразу заканчиваются ошибкой и не задерживают рассылку во второй мессенджер.

В последнем случае в отчёте будет много неудачных отправок, и рассылку в этот мессенджер придётся повторить позже. Здесь тоже помогает `on_sent`: отмечайте человека, только если нужная доставка удалась.

## Те, кто заблокировал бота

Писать человеку, который заблокировал бота, бесполезно, а каждая такая попытка тратит лимит. Чтобы сразу отмечать таких у себя, передайте `on_unreachable`:

```python
async def mark_blocked(platform: str, user_id: int, exc: Exception) -> None:
    await db.mark_blocked(platform, user_id)


hub = Hub(max_bot, telegram_bot, on_unreachable=mark_blocked)
```

Хук вызывается и из `send`, и из `broadcast`, когда мессенджер ответил, что этому человеку написать нельзя.

Узнать о блокировке можно и раньше, из хендлера `@dp.chat_status()`, см. [Человек заблокировал бота](handlers.md#человек-заблокировал-бота). Вместе эти два способа держат список получателей чистым. Когда человек вернётся и снова запустит бота, тот же хендлер получит событие с `reachable=True`, и отметку можно снять.

## Кнопки

У `send` и `broadcast` есть параметр `keyboard`, как у `ctx.reply`:

```python
from matele import Button, Keyboard

await hub.broadcast(people, "Новая акция", Keyboard([[Button("Подробнее", url="https://example.com/sale")]]))
```

Кнопки с данными тоже работают: нажатие придёт в обычный хендлер `@dp.callback()`.

## Чего Hub не делает

`Hub` отправляет только текст с кнопками. Чтобы разослать фото или файл, отправляйте их сами через `bot.send_file()` и соблюдайте паузы между отправками.

Текст у всех получателей один. Если сообщение нужно подставить под каждого человека, например обратиться по имени, вызывайте `hub.send()` в цикле: ограничение скорости при этом работает так же.

```python
for person in people:
    await hub.send(person.accounts, f"{escape(person.name)}, ваш заказ готов")
```
