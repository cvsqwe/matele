# Групповые чаты

Бот работает и в личных чатах, и в группах. Хендлеры те же самые: `ctx.reply()` отвечает туда, откуда пришло событие, в группу или в личный чат.

```python
from matele import GROUP, ChatType, Context


@dp.command("stats", ChatType(GROUP))
async def stats(ctx: Context):
    count = await db.messages_in_chat(ctx.platform, ctx.chat_id)
    await ctx.reply(f"В этом чате {count} сообщений")
```

## Где произошло событие

| Атрибут | В личном чате | В группе |
|---|---|---|
| `ctx.chat_type` | `matele.PRIVATE` | `matele.GROUP` |
| `ctx.chat_id` | `None` | id группы |
| `ctx.user` | собеседник | участник, который написал или нажал кнопку |

Хендлер без фильтров получает события отовсюду. Чтобы команда работала только в группах или только в личных чатах, добавьте фильтр `ChatType`:

```python
from matele import PRIVATE


@dp.command("settings", ChatType(PRIVATE))
async def settings(ctx: Context): ...
```

Id группы в MAX и Telegram, как и id людей, никак не связаны между собой. Если храните что-то о группе, храните пару `(ctx.platform, ctx.chat_id)`.

## Чтобы бот видел все сообщения

По умолчанию бот в группе видит не всё, и это первое, на чём спотыкаются: бот добавлен, команды работают, а на обычные сообщения он не реагирует.

В Telegram у ботов включён режим приватности: бот получает только команды и ответы на свои сообщения. Чтобы получать все сообщения, отключите его в [@BotFather](https://t.me/BotFather) командой `/setprivacy`, потом удалите бота из группы и добавьте снова, иначе настройка не применится. Другой вариант: сделать бота администратором группы.

В MAX бот должен быть администратором группы с правом читать все сообщения.

Если боту нужны только команды и кнопки, ничего менять не надо.

## Команды для других ботов

Если в группе несколько ботов, команды пишут с адресом: `/help@other_bot`. Такие команды бот пропускает, они адресованы не ему. Команды без адреса и с адресом самого бота обрабатываются как обычно.

## Ответ в личку

`ctx.send_private()` пишет человеку в личный чат с ботом, даже если команда пришла из группы. Это нужно для всего, что не должно быть видно остальным:

```python
from matele import BotApiError, is_unreachable


@dp.command("mycode", ChatType(GROUP))
async def my_code(ctx: Context):
    try:
        await ctx.send_private(f"Ваш код: {await codes.issue(ctx.user.id)}")
    except BotApiError as exc:
        if not is_unreachable(exc):
            raise
        link = ctx.bot.deep_link(ctx.bot.me.username, "code")
        await ctx.reply(f"Сначала откройте личный чат с ботом: {link}")
        return
    await ctx.reply("Отправил код в личные сообщения")
```

Мессенджеры не дают боту написать человеку первым. Если человек ни разу не открывал личный чат с ботом или заблокировал его, отправка закончится ошибкой, для которой `is_unreachable()` вернёт `True`. Пример выше в этом случае даёт ссылку, по которой человек откроет бота.

## Вход и выход участников

```python
from matele import escape


@dp.member_update()
async def members(ctx: Context):
    update = ctx.member_update
    if update.is_me:
        if update.joined:
            await ctx.reply("Спасибо, что добавили! Команды: /help")
        return
    if update.joined:
        await ctx.reply(f"Добро пожаловать, {escape(update.member.name)}!")
```

Это событие приходит в четырёх случаях: человек вошёл в группу, человек вышел, бота добавили, бота удалили. Что именно случилось, говорят поля `ctx.member_update`:

| Поле | Что в нём |
|---|---|
| `member` | кто вошёл или вышел |
| `joined` | `True`, если вошёл, `False`, если вышел |
| `is_me` | событие про самого бота: его добавили в группу или удалили из неё |
| `from_user` | кто это сделал. Если человек вошёл или вышел сам, это он же |
| `chat_id` | id группы |

Событие про самого бота полезно, чтобы завести запись о группе, когда бота добавили, и убрать её, когда удалили:

```python
@dp.member_update()
async def track_groups(ctx: Context):
    update = ctx.member_update
    if not update.is_me:
        return
    if update.joined:
        await db.add_group(ctx.platform, update.chat_id, added_by=update.from_user.id)
    else:
        await db.remove_group(ctx.platform, update.chat_id)
```

Когда бота удалили, ответить в группу уже нельзя: `ctx.reply()` в этом хендлере закончится ошибкой.

## Состояния в группах

Состояние хранится отдельно для каждого человека в каждой группе. Если человек начал заполнять анкету в одной группе, его сообщения в другой группе или в личке не будут считаться ответами на её вопросы. Два участника одной группы тоже не мешают друг другу: у каждого своё состояние.

Многошаговые сценарии в группах работают, только если бот видит обычные сообщения (см. выше). Иначе ответы на вопросы до него не дойдут.

## Кнопки и меню в группах

Кнопку под сообщением бота может нажать любой участник группы, а не только тот, кому бот отвечал. `ctx.user` в хендлере кнопки это тот, кто нажал.

Если действие доступно не всем, проверяйте, кто нажал. Частый приём: положить id нужного человека в данные кнопки и сравнить:

```python
@callback("poll:close")
class ClosePoll(CallbackData):
    poll_id: int
    author_id: int


@dp.callback(ClosePoll)
async def close_poll(ctx: Context, payload: ClosePoll):
    if ctx.user.id != payload.author_id:
        await ctx.answer("Закрыть опрос может только автор", alert=True)
        return
    await polls.close(payload.poll_id)
    await ctx.edit("Опрос закрыт")
```

То же касается [меню в одном сообщении](menus.md): в группе все видят меню всех участников и могут нажимать их кнопки. Чаще всего меню оставляют только для личных чатов.

Уведомление с `alert=True` в MAX дополнительно приходит сообщением в личный чат того, кто нажал, а не в группу.

## Чего нет

Каналы matele пока не обрабатывает, только личные чаты и группы. Сообщения из каналов пропускаются.

Управление группой (закрепить сообщение, удалить участника, назначить администратора) в общий слой не входит, потому что устроено в мессенджерах по-разному. Оно доступно через клиенты API, см. [API мессенджеров](platform-api.md).
