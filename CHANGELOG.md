# Изменения

Версии нумеруются как `MAJOR.MINOR.PATCH`. До 1.0 ломающие изменения возможны в любой версии `0.x`, но каждое такое изменение записывается здесь в разделе «Ломающие изменения» вместе с тем, что нужно поправить в своём коде. Исправления без изменения API выходят как `PATCH`.

## Не выпущено

Исправления:

- неверный токен больше не выглядит как сетевой сбой. Если при запуске мессенджер не принял токен (`getMe` ответил 401, а у Telegram 404 на токен неправильного вида), `run_polling()` сразу останавливается с `InvalidTokenError`, вместе с остальными мессенджерами. Сетевые ошибки и 5xx по-прежнему повторяются
- если один мессенджер остановил `start_polling()` ошибкой, polling остальных тоже останавливается, а их начатые хендлеры получают `shutdown_timeout`, как при обычной остановке. Раньше они продолжали работать с уже закрытыми клиентами
- `Webhook(at_least_once=True)` отвечал 200 и тогда, когда остановка процесса прервала хендлер, и событие терялось. Теперь в этом случае ответ 503, и мессенджер присылает событие снова
- новое сообщение больше не может прийти дважды из-за повтора. Отправку matele повторяет после 429 и 503, но не после 502 и 504: при них сообщение могло уже уйти. Остальные запросы повторяются, как раньше
- у `BotUnavailableError` появилось поле `maybe_sent`: `True`, если запрос мог дойти до мессенджера. `Hub` в этом случае не повторяет отправку, чтобы человек не получил сообщение дважды
- в Telegram поток, который нельзя перемотать, копируется во временный файл перед отправкой. Раньше повтор после 429 или после ошибки HTML в подписи уходил с уже прочитанным потоком, и файл не доходил
- в MAX `ctx.edit(None, keyboard)` с неподходящей для MAX ссылкой в кнопке заменял текст сообщения строкой со ссылкой. Теперь текст остаётся, кнопка становится неактивной, а в лог пишется предупреждение. Перенесённые в текст ссылки больше не начинаются с пустых строк, когда текста нет
- в MAX правка сообщения с фото, видео, аудио, файлом, стикером или геолокацией больше не удаляет вложение. MAX при правке заменяет все вложения сообщения, и `ctx.edit()`, `ctx.show()` и `bot.edit_message()` отправляли только клавиатуру, поэтому, например, снятие кнопок под фото удаляло само фото. Теперь вложения прикладываются заново. Вложения сообщений, которые бот отправил или на которых нажали кнопку, он помнит; для незнакомого сообщения делается один запрос `GET /messages/{id}`
- в MAX ответ на нажатие без текста уходит без пустого `notification`. Если MAX такой ответ не примет, matele повторит его с пустым `notification`, как раньше
- `FakeBot()` (MAX) больше не нумерует сообщения: `ctx.show()` в тестах ведёт себя как в настоящем MAX и отправляет меню заново внизу. `FakeBot(platform=TELEGRAM)` нумерует, как раньше. Тест, который рассчитывал на правку меню на месте под MAX, теперь падает: передайте в нём `platform=TELEGRAM` или ждите нового сообщения

## 0.1.0 (2026-11-10)

Первая версия. Что в ней есть:

- общий слой для MAX и Telegram: сообщения, кнопки, файлы, ответы на сообщения, статус «печатает…»
- роутеры, фильтры, middleware, состояния с хранилищами в памяти, SQLite и Redis
- типизированные данные кнопок
- групповые чаты и события входа и выхода участников
- меню в одном сообщении (`ctx.show()`)
- меню команд из `@dp.command(..., description=...)`
- мини-приложения: кнопка открытия и проверка `initData`
- рассылки во все мессенджеры человека (`Hub`)
- long polling и вебхуки (ASGI)
- весь MAX Bot API с моделями из официальной схемы, `TelegramApi.call()` для любого метода Telegram
- `FakeBot` для тестов без сети
- `escape()` для текста, который пришёл снаружи: сообщения уходят как HTML
- подпись данных кнопок (`callback_secret`), чтобы бот принимал только свои кнопки
- доставка «минимум один раз» для polling и вебхуков (`at_least_once=True`)
- ограничение числа одновременно обрабатываемых событий (`concurrency`, `max_pending`)
- остановка по Ctrl+C и SIGTERM с ожиданием начатых хендлеров
- блокировка разговора между процессами в `RedisStorage`
- продолжение рассылки после перезапуска (`on_sent`)
- лимит на размер скачиваемых файлов (`max_download`, по умолчанию 50 МБ)
- документация на сайте https://cvsqwe.github.io/matele/
