# Планы

Что уже сделано и что впереди. Порядок внутри разделов примерный.

## Готово

- общие типы, ошибки, типизированные кнопки
- роутеры, диспетчер, фильтры, middleware, состояния
- транспорты MAX и Telegram, весь MAX Bot API с моделями из официальной схемы
- групповые чаты, вебхуки, хранилища SQLite и Redis
- FakeBot для тестов без сети

## До версии 0.1

Проверка на живых ботах. Всё пока проверено на фейковых серверах. Нужно прогнать пример и основные сценарии на настоящих ботах в обоих мессенджерах, особенно группы в MAX, загрузку файлов и вебхуки.

Мини-приложения:
- кнопка, которая открывает мини-приложение в MAX и Telegram (в MAX адрес задаётся в кабинете бота, в Telegram у каждой кнопки свой)
- проверка подписи `initData` для обоих мессенджеров, со сроком действия
- пример: мини-приложение и сервер на FastAPI, который принимает из него данные и отвечает через бота

Меню в одном сообщении. Экраны меню открываются в одном сообщении, которое редактируется, вместо того чтобы засыпать чат новыми.

Рассылки. Отправка человеку во все мессенджеры, где он есть, с ограничением скорости под лимиты MAX и Telegram и повторами при временных ошибках.

Отправка не только текста:
- фото, видео и аудио в общем слое, а не только документы
- ответ на конкретное сообщение
- статус «печатает…» на время долгой обработки

Команды в меню мессенджера. Команды, зарегистрированные через `@dp.command`, с описаниями сами попадают в меню бота в MAX и Telegram.

Инфраструктура:
- CI на Windows вдобавок к Linux
- покрытие тестами в CI
- CHANGELOG и правила версий: что считается ломающим изменением
- публикация на PyPI из GitHub Actions по тегу

Документация. Сайт с руководством на русском: первый бот, кнопки, состояния, группы, вебхуки, мини-приложения, тестирование. Потом английская версия.
